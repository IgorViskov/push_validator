# ReviewAgent

Агент, который проверяет изменения **перед `git push`** и решает: пропустить пуш или
остановить. Живёт в докер-образе, обслуживает несколько git-репозиториев, держит граф кода
в актуальном состоянии и объясняет каждое решение.

Ставится один раз: `docker compose up -d`, открыть админку, указать путь к репозиторию.
Дальше `git push` сам спрашивает у агента разрешение.

```
git push
  └─ pre-push ──HTTP──> агент ──> обновить граф кода по изменённым файлам
                          │
                          ├─ triage    сложность + затронутые символы + поиск инъекций
                          ├─ impact    кто вызывает изменённые символы (граф кода)
                          ├─ review    ReAct-анализ диффа и вызывающего кода
                          ├─ validate  независимая проверка другой моделью
                          ├─ arbiter   разрешение расхождений между ними
                          └─ report    вердикт
  └─ exit 0 / exit 1
```

## Что он делает такого, чего не делает линтер

Проверяет то, чего **нет в диффе**. Дифф из одного файла может сломать четыре вызывающих
места в трёх других файлах — по тексту диффа этого не видно ни человеку, ни модели.
Агент держит граф кода репозитория (Roslyn → Neo4j) и на каждом пуше спрашивает у него,
кто вызывает изменённые символы.

Пример из демонстрационного репозитория: в методе добавлен параметр, дифф — три строки.

```
Маршрут по графу состояний:
  triage → impact: изменён публичный контракт — вызывающий код нужно проверить независимо от сложности
  impact → review: подключено фрагментов влияния: 10
  review → validate: первичный анализ завершён
  validate → arbiter: оба мнения собраны
  arbiter → report: вердикт вынесен: подтверждено 1, снято 0
  report → конец: пуш остановлен: критических находок 1

[СТОП] [Анализ] src/ShopDemo.Domain/Pricing/PriceCalculator.cs: Изменена публичная сигнатура
метода CalculateTotal, добавлен параметр shippingCost. Это нарушает совместимость
с вызывающим кодом, который использует старую сигнатуру и не передаёт shippingCost.
```

## Запуск

Нужны Docker и OpenAI-совместимый сервер моделей — например [LM Studio](https://lmstudio.ai)
на той же машине.

```bash
cp .env.example .env
```

В `.env` обязательно задать:

| Переменная | Что это |
|---|---|
| `REPOS_ROOT` | каталог хоста с вашими репозиториями; монтируется в контейнер как `/repos` |
| `LLM_ENDPOINT` | адрес сервера моделей (`http://host.docker.internal:1234/v1` для LM Studio) |
| `LLM_API_KEY` | токен, если сервер моделей его требует |
| `MODEL_*` | имена моделей по ролям — те, что отдаёт `GET /v1/models` вашего сервера |

```bash
docker compose up -d
```

Админка — <http://localhost:8080>; порт задаётся `AGENT_PORT`. Если 8080 занят, меняйте
`AGENT_PORT` и `HOOK_PUBLIC_URL` вместе: адрес агента вписывается в текст хука, и после
смены порта хук нужно переустановить из админки.

Дальше в админке: указать путь к репозиторию **так, как его видит агент**. Каталог хоста
`C:/Projects/my-app` при `REPOS_ROOT=C:/Projects` виден агенту как `/repos/my-app` —
админка сама покажет, что нашла в `/repos`.

Подключение репозитория делает три вещи: записывает `.git/hooks/pre-push`, заводит запись
в реестре и запускает полную индексацию графа кода.

## Как работает хук

Хук — скрипт на POSIX `sh`, из внешних инструментов ему нужен только `curl` (и то и другое
входит в поставку git на всех платформах). Порядок действий:

1. проверяет живость агента (`GET /api/health`);
2. если агент не отвечает — пытается поднять контейнер (`Hook__AutostartCommand`) и ждёт
   готовности до `Hook__StartupWaitSeconds`;
3. собирает дифф проверяемого диапазона по данным, которые git передаёт на stdin;
4. отправляет дифф на `POST /api/review`;
5. печатает отчёт и возвращает код выхода.

Если агента поднять не удалось, по умолчанию пуш **пропускается** (`HOOK_ON_UNAVAILABLE=allow`):
неработающий ревьюер не должен парализовать работу команды. Обратное поведение — `block`.

Последнее слово остаётся за человеком:

```bash
REVIEW_AGENT_FORCE=1 git push
```

## Настройка

Все настройки задаются переменными окружения в `docker-compose.yml` / `.env`. Двойное
подчёркивание — разделитель уровней: `Guardrails__Budget__MaxTokens` читается приложением
как `Guardrails:Budget:MaxTokens`.

Страница **Настройки** в админке показывает применившиеся значения и имя переменной для
каждого — редактировать их из браузера нельзя намеренно: настройка, изменённая в UI, живёт
до перезапуска контейнера и расходится с тем, что записано в compose-файле.

Полный список с пояснениями — в [`.env.example`](.env.example).

### Модели и роли

Три роли, и это не декорация — у каждой свои требования:

| Роль | Этапы | Что требуется от модели |
|---|---|---|
| `Orchestration` | triage, arbiter | короткий ответ строго по схеме; выполняется 2–3 раза за прогон, поэтому скорость дороже глубины |
| `Execution` | review | понимание кода и вызов инструментов; **две** модели — дешёвая для тривиальных правок и сильная для остальных |
| `Validation` | validate | второе независимое мнение; **другое семейство моделей**, иначе арбитр сверяет два прогона одной модели |

Для `Execution` работает когнитивный роутинг: берётся самая дешёвая модель, чей
`CostEfficiency` не ниже оценённой сложности изменений.

Замеры на локальных моделях и обоснование выбора — [`docs/MODELS.md`](docs/MODELS.md).

## Предохранители

Агент тратит время, читает чужой репозиторий и принимает решение о пуше. У каждого из этих
свойств есть ограничитель.

| Предохранитель | Что ограничивает | Что происходит при срабатывании |
|---|---|---|
| Бюджет прогона | стоимость, токены, время, обращения к моделям и к графу | маршрут сворачивается к отчёту |
| Ретраи | сетевые сбои и временные отказы (429, 5xx) | до 2 повторов с экспоненциальной задержкой; на 401/403/404 повторов нет |
| Предохранитель модели | модель, падающая раз за разом | после 2 неудач подряд обращения к ней в этом прогоне не выполняются |
| Квоты инструментов | петли ReAct | `read_file` 25, `search_files` 15, `git_log` 3, `graph_impact` 5 за прогон |
| Потолок витков ReAct | цикл «модель просит инструмент → получает отказ → просит снова» | не более 6 витков и 60 вызовов инструментов на прогон |
| Закрытые файлы | утечку секретов в промпт | `.env`, `*.pem`, `launchSettings.json` и подобные не читаются даже внутри репозитория |
| Приёмка вывода | выдумки модели | пустые находки и дубликаты отбрасываются, ссылки на несуществующие файлы снимаются |
| Граница доверия | prompt injection | строки, обращённые к модели, дают критическую находку, которую арбитр не вправе снять |
| Предел переходов | ошибку в условии перехода | не более 12 переходов по графу состояний |

**Fail-closed.** Если модель недоступна или вернула неразборчивый ответ, шаг добавляет
критическую находку и блокирует пуш — а не «тихо» его разрешает.

## Кто принимает решение

Три способа свести мнения нескольких агентов различаются, и в сценарии участвуют все три:

- **консенсус** — `review` и `validate` работают независимо и не видят находок друг друга;
  совпавшая находка подтверждается арбитром без разбирательства;
- **арбитраж** — расхождения разрешает отдельная роль, а не правило «любая критическая
  находка блокирует»: иначе решение принимает тот из агентов, кто мнительнее;
- **диктатор** — последнее слово у человека: агент возвращает вердикт, а продавить пуш
  можно переменной `REVIEW_AGENT_FORCE`.

## Требования

.NET 10 SDK (для разработки), Docker, git. Сборка и запуск без Docker:

```bash
dotnet run --project src/ReviewAgent.Web
```

В этом случае граф нужно поднять отдельно (`docker compose up -d graph`) и поправить
`Graph:Uri` на `bolt://localhost:7687`.
