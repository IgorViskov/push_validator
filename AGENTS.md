# AGENTS.md

Инструкции для AI-агентов и контрибьюторов, работающих с этим репозиторием.

## Что это

CLI-агент, который **проверяет изменения перед `git push`**: анализирует дифф с помощью
нескольких LLM и либо разрешает пуш (`exit 0`), либо приостанавливает его (`exit 1`).
Задуман как pre-push git-hook.

Три ключевые идеи:
- **Граф состояний** — сценарий проверки собран не как цепочка шагов, а как граф: состояние
  возвращает имя следующего, поэтому маршрут ветвится и допускает возврат назад.
- **ReAct** — на этапе анализа модель сама вызывает инструменты (`read_file`, `git_log`,
  `search_files`, `graph_impact`), чтобы дочитать контекст вне диффа. Цикл Reason→Act→Observe
  крутит `FunctionInvokingChatClient` из Microsoft.Extensions.AI.
- **Когнитивный роутер** — из заданных в конфиге моделей выбирает подходящую под задачу:
  по роли (Orchestration / Execution / Validation) и, для анализа, по соотношению
  «сложность изменений ↔ стоимость/ум модели» (`CostEfficiency`).

За вызывающим кодом агент ходит в соседнюю систему — сеть агентов
[LLmSeracher](../LLmSeracher) с графом кода в Neo4j, по протоколу A2A с делегированием
полномочий. Отсюда `ProjectReference` на `LLmSeracher.Core`.

## Стек

- .NET 10 (`net10.0`), C# с `Nullable` и `ImplicitUsings`.
- Microsoft.Extensions.AI (+ `.OpenAI`) поверh OpenAI SDK — общается с любым
  OpenAI-совместимым endpoint (OpenRouter, LM Studio, корпоративные шлюзы).
- Microsoft.Extensions.{DependencyInjection, Configuration, Logging}.
- Один проект, без сторонних библиотек для git — обёртка над процессом `git`.

## Команды

```bash
# Сборка (из корня; решение LLMAgent.sln подхватывается автоматически)
dotnet build

# Запуск проверки конкретного репозитория
dotnet run --project LLMAgent/LLMAgent.csproj -- "C:\path\to\target\repo"
# Без аргумента берётся текущий каталог.

# Коды выхода: 0 — пуш разрешён; 1 — пуш приостановлен либо ошибка.
```

**Автотестов в проекте нет** (единственный `.csproj` — сам агент). «Тест работоспособности» =
запуск бинаря против репозитория, в котором есть незапушенные изменения, и проверка вывода/кода
выхода. Нужен хотя бы один доступный LLM-endpoint (см. ниже).

## Конфигурация

Источник — `LLMAgent/appsettings.json`, секция `Apis` (массив API, у каждого — список моделей):

```jsonc
{
  "Apis": [{
    "Name": "OpenRouter",
    "ApiKey": "",                 // пустой ключ → ApiKeyCredential бросит ArgumentException
    "Endpoint": "https://openrouter.ai/api/v1",
    "Models": [{
      "Name": "openai/gpt-oss-120b:free",
      "Role": "Orchestration",    // Orchestration | Execution | Validation
      "Priority": 1,              // для Orchestration/Validation берётся модель с макс. Priority
      "CostEfficiency": 4         // для Execution: чем выше — тем «умнее и дороже»
    }]
  }]
}
```

- **Ключи через переменные окружения**: `Apis__0__ApiKey`, `Apis__1__Endpoint`, … перекрывают
  JSON (`AddEnvironmentVariables`). Локально это делает `LLMAgent/Properties/launchSettings.json`
  (профиль `Local`).
- **Секреты не коммитить.** `launchSettings.json` в `.gitignore`. Реальные ключи держать только
  в env / секрет-хранилище, не в `appsettings.json`.

Секции `A2A` и `Impact` управляют выходом в сеть агентов LLmSeracher:

```jsonc
{
  "A2A": {
    "SelfId": "reviewer",                                 // попадает в issuer токена
    "HostUrl": "http://localhost:5080",                   // хост агентов LLmSeracher
    "SigningSecret": "dev-shared-secret-for-homework-only" // ОБЯЗАН совпадать с секретом сети
  },
  "Impact": {
    "Enabled": true,
    "ComplexityThreshold": 4,   // с какой сложности идти в граф
    "MaxSymbols": 5,            // сколько символов попадёт в запрос
    "MaxContextChars": 6000,    // бюджет блока контекста влияния в промпте
    "MaxArbiterRetries": 1      // сколько раз арбитр может назначить второй проход
  }
}
```

Секрет подписи общий у обеих систем только потому, что это учебный стенд: при расхождении
секретов ретривер вернёт «подпись не совпадает», и сценарий уйдёт в ветку деградации —
это удобный способ показать проверку полномочий вживую.

Секция `Guardrails` задаёт потолки прогона, ретраи, предохранитель моделей, квоты
инструментов, список закрытых для чтения файлов и путь журнала — состав и значения
по умолчанию описаны в [HOMEWORK18.md](HOMEWORK18.md). Цены моделей задаются рядом с ними:

```jsonc
{ "Name": "…", "Role": "Execution", "CostEfficiency": 8,
  "PricePerMillionInput": 0.15, "PricePerMillionOutput": 0.60 }
```

## Архитектура

Поток запроса (`Agent.Run`) — обход графа состояний, который водит `AgentEngine`:

```
Diff (GitService)
  └─> triage ──> impact ──> review ──> validate ──> arbiter ──> report
       │           ▲          │                        │          │
       └───────────┼──────────┘ (мелкая правка)        │          └─> exit 0/1
                   └──────────────────────────────────-┘ (арбитру не хватило фактов)
```

Переход выбирает само состояние: оно возвращает `AgentTransition` с именем следующего узла
и причиной. Причина не служебная — она печатается в отчёте как маршрут прогона.

| Компонент | Файл | Роль |
|-----------|------|------|
| Точка входа, DI | `LLMAgent/Program.cs` | читает конфиг, регистрирует сервисы, ловит коды выхода |
| Вход в сценарий | `Modules/Agent/Agent.cs` | проверки репозитория + `_engine.Run(AgentStates.Triage, context)` |
| Машина состояний | `Modules/Agent/AgentEngine.cs` | ищет узел по имени, водит контекст, ограничивает число переходов |
| Контракт узла | `Modules/Agent/IAgentState.cs` | `IAgentState`, `AgentTransition`, имена состояний и этапов |
| Состояния | `Modules/Agent/States/*State.cs` | triage / impact / review / validate / arbiter / report |
| Регистрация состояний | `Modules/Agent/States/StateInstaller.cs` | `AddSingleton<IAgentState, …>` |
| Выход в сеть агентов | `Modules/Impact/ImpactService.cs` | задача агенту `retriever` + подписанный токен `context:read` |
| Разбор диффа | `Modules/Impact/DiffSymbols.cs` | затронутые типы/методы и файлы без участия модели |
| Контекст в промпт | `Modules/Impact/ImpactRenderer.cs` | фрагменты графа → блок промпта и строки для консоли |
| Когнитивный роутер | `Modules/Router/CognitiveRouter.cs` | выбор модели по роли/сложности |
| Чат-обёртка | `Modules/Chats/Chat.cs` | `IChatClient` + function-calling + structured output; свободный ответ читается потоково |
| Статусы анализа | `Modules/Chats/ChatActivityRenderer.cs` | превращает поток ответа в консольные статусы (размышляет / пишет / вызывает инструмент) |
| Git | `Modules/Git/GitService.cs` | дифф/лог/проверка репозитория через процесс `git` |
| Инструменты | `Modules/Tools/RepoToolFactory.cs` | `read_file`, `git_log`, `search_files`, `graph_impact` |
| Промпты | `Prompts/Prompt.cs` | все системные и пользовательские сообщения |
| Модели данных | `Models/*.cs` | `ApiSettings`, `ModelSetting`, `Finding`, `ImpactOptions`, `*Result` |

Контекст между состояниями передаётся через мутируемый `LlmContext` (дифф → сложность и
затронутые символы → контекст влияния → находки → вердикт арбитра → решение `AllowPush`).
Из-за возвратов в графе состояние обязано класть находки через `ReplaceFindings(stage, …)`,
а не `Findings.AddRange`: иначе второй проход удвоит список.

### Ветвления

| Где | Условие | Куда |
|-----|---------|------|
| `triage` | `Impact:Enabled=false`, сложность ниже `Impact:ComplexityThreshold` или символов не нашлось | сразу `review` |
| `impact` | граф не ответил | `review` + `Info`-находка «граф недоступен» |
| `review` | идёт второй проход (`ArbiterRetries > 0`) | сразу `arbiter`, минуя `validate` |
| `arbiter` | критических находок нет | `report` (консенсус) |
| `arbiter` | `needsContext` и лимит проходов не исчерпан | назад в `impact` с уточнённым запросом |
| `report` | есть критические находки | вопрос пользователю, `exit 1` при отказе |

### Предохранители

Слой `Modules/Safety` устроен как набор узких мест: каждое действие, которое стоит денег
или выходит наружу, проходит через один объект, а не через проверку, повторённую в каждом
состоянии, — там её рано или поздно забыли бы поставить.

| Компонент | Файл | За что отвечает |
|---|---|---|
| Метрики прогона | `Modules/Safety/RunMetrics.cs` | исход, время, стоимость, счётчики инструментов и делегирований |
| Потолки | `Modules/Safety/RunGuard.cs` | бюджет: деньги, токены, время, обращения к моделям, делегирования |
| Шлюз обращений | `Modules/Safety/ModelGate.cs` | ретраи, предохранитель модели, учёт расхода, fail-closed при отказе |
| Приёмка вывода | `Modules/Safety/FindingsGuard.cs` | пустые находки, дубликаты, выдуманные пути, лимит на этап |
| Поиск инъекций | `Modules/Safety/InjectionScanner.cs` | строки недоверенного текста, обращённые к модели |
| Квоты инструментов | `Modules/Safety/ToolQuota.cs` | лимит вызовов и список закрытых файлов |
| Журнал прогона | `Modules/Safety/MetricsWriter.cs` | JSON-запись в `logs/` |

Правила, которые легко нарушить при доработке:

- **Все обращения к моделям идут через `ModelGate.Ask`.** Он возвращает `null` при любом
  отказе; состояние обязано трактовать `null` как «ответа нет» и включить свой запасной
  путь, а не считать, что замечаний не нашлось.
- **Находки моделей проходят через `FindingsGuard.Validate`** до попадания в контекст.
- **Находки этапа `Stages.Security` арбитражу не подлежат** — вердикт о попытке инъекции
  не должна выносить модель, на которую эта инъекция направлена.
- **Сбой состояния не роняет прогон**: `AgentEngine.Execute` ловит исключение, ставит
  критическую находку `Stages.Engine` и сворачивает маршрут к отчёту.
- **Аварийная остановка живёт в движке** (`AgentEngine.Redirect`), а не в состояниях.

### Роли и разрешение конфликтов

`review` и `validate` работают независимо и не видят находок друг друга — иначе второе мнение
не второе. Их расхождения разрешает `arbiter` (модель роли `Orchestration` с промптом
`Prompt.Arbitration`): подтверждённые находки остаются критическими, снятые понижаются до
`Info` с обоснованием — не удаляются, чтобы решение было проверяемым. Последнее слово
остаётся у человека в `report`.

## Контракт поведения

- **Выбор диффа** (`GitService.GetLatestChanges`): сначала незапушенные коммиты (`@{u}..HEAD`),
  иначе последний коммит (`HEAD~1..HEAD`), иначе рабочее дерево (`diff HEAD`). Пусто → `exit 0`.
- **Гейт fail-closed**: если обращение к модели упало или ответ не распарсился, состояние
  добавляет **критическую находку** (не «тихо разрешает» пуш). Любая критическая находка
  приостанавливает пуш до явного `y/yes/да` от пользователя в `ReportState`.
  Исключение — отказ графа кода: он даёт `Info`-находку и деградацию, потому что контекст
  влияния уточняет анализ, а не заменяет его.
- **Отказ арбитра** не снимает находки: без вердикта критические остаются в силе.
- **Severity**: `Critical` блокирует пуш; `Warning`/`Info` — информативны.

## Соглашения

- **Язык — русский**: комментарии, XML-док, промпты, логи, сообщения пользователю. Держим единообразие.
- Ошибки — через `Modules/ErrorsModule/Errors.cs` и типизированные исключения
  (`ExitException`, `NoChatException`).
- Структурный вывод и инструменты намеренно **разнесены по разным запросам** (function-calling +
  принудительная JSON-схема конфликтуют на многих моделях) — см. `Chat.GetAnswer` vs `GetAnswer<T>`.
- Каталог `Middelwares` (с опечаткой) удалён вместе с пайплайном: шаги переехали в
  `Modules/Agent/States` как состояния графа.

## Как расширять

**Добавить состояние** (частый источник ошибок — забыть один из трёх пунктов):
1. Класс `…State : IAgentState` с `Name` из `AgentStates` и методом `Run`, возвращающим
   `AgentTransition.To(…)` или `AgentTransition.Finish(…)`.
2. Добавить имя в `AgentStates` и зарегистрировать в `StateInstaller.AddStates`.
3. Направить в него переход из того состояния, откуда он должен случаться, — точку входа
   в граф задаёт `Agent.Run`, остальной маршрут живёт в самих состояниях.

Состояние, в которое можно вернуться, обязано быть идемпотентным по находкам:
класть их через `LlmContext.ReplaceFindings`, а не добавлять.

**Добавить инструмент ReAct**: новый `AIFunctionFactory.Create(...)` в `RepoToolFactory.Build`;
схема выводится из сигнатуры C#-метода, ручной JSON-Schema не нужен. Доступ за пределы репозитория
обязан спрашивать `IUserPermission`.

**Добавить навык чужого агента**: `ImpactService` показывает шаблон — собрать `AgentTask`,
выпустить токен через `DelegationService.Issue(audience, task, scope)` и разобрать поток
`AgentEvent`. Идентификаторы агентов, навыков и полномочий берутся из `LLmSeracher.Core.Agents`,
своих строковых копий заводить не надо.

**Добавить модель/провайдера**: запись в `Apis` (`appsettings.json`) с нужными `Role`/`Priority`/
`CostEfficiency`; ключ — через env.

## Известные ограничения (на момент написания)

- **Validation требует своей модели.** Если для роли `Validation` не задано ни одной модели —
  `CognitiveRouter` бросит `NoChatException` (пуш будет заблокирован через общий catch). Удобной
  деградации «нет роли — пропустить шаг» пока нет.
- **Нет фолбэка между моделями одной роли** при недоступности endpoint (выбирается одна
  модель; предохранитель размыкается, но на другую модель роли прогон не переходит).
- **Предохранитель модели без полуоткрытого состояния**: прогон живёт минуты, ждать
  восстановления не у кого — упавшая модель считается упавшей до конца прогона.
- **Стоимость точна лишь настолько, насколько заполнены цены** в `Apis[].Models[]`
  (`PricePerMillionInput`/`Output`). Без них бюджет держится на лимите токенов, а не денег;
  если провайдер не вернул `usage`, токены оцениваются по длине текста.
  Роль `Orchestration` теперь исполняет и триаж, и арбитраж, поэтому мёртвый слаг модели этой
  роли обезоруживает оба: триаж уйдёт на сложность 5 по умолчанию, арбитраж — в fail-closed.
- **Контекст влияния требует поднятой инфраструктуры LLmSeracher** (Neo4j + `AgentHost` + граф,
  наполненный по анализируемому решению). Без неё ветка `impact` работает, но всегда уходит
  в деградацию: граф знает только то решение, которое было проиндексировано.
- В примере конфигурации `Validation` указывает на **локальную LM Studio** (`localhost:1234`) —
  без запущенного локального сервера этот шаг даёт критическую находку (это корректный fail-closed,
  но «зелёный» прогон требует поднятой LM Studio либо validation-модели у облачного провайдера).
- `AgentEngine` зарегистрирован как singleton с мутабельным состоянием — рассчитан на один прогон
  за процесс.
